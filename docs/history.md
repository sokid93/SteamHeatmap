# Project history

What has shipped and why, newest first. This is the narrative record, not
working context: rules and current open items live in the `CLAUDE.md` files,
decisions in `adr/` and `rfc/`, and the process's own evolution in
[`methodology.md`](methodology.md).

As of 2026-11-18 — MVP fully working end to end, redesigned map, visual pass shipped, out-of-catalog search shipped. **All issues closed** (#1 and its full tree, including #22's sub-issues).

- **Working context split, 2026-11-18**: `CONTEXT.md` was one file mixing a glossary, architecture notes and this history, and nothing loaded it automatically. It became a root `CLAUDE.md` (always loaded), `analysis/CLAUDE.md` and `web/CLAUDE.md` (loaded when a file in that folder is touched), two path-scoped rules in `.claude/rules/` for the invariants that cross the C#/Python boundary, `CONTEXT.md` as a pure glossary, and this file.

- **Decision records split, 2026-11-18**: the sixteen ADRs became eleven ADRs (`adr/`, renumbered 001–011 without gaps), four RFCs (`rfc/`, RFC-001–004: top-N scope, hosting, frontend stack, homepage styling — pragmatic choices expected to be revisited rather than fixed architecture) and one reference document (`docs/steam-web-api.md`, the former Steam API ADR, mostly verified endpoint mechanics). Every reference in docs and code comments was rewritten. Commits, issues and PRs from before this date use the old numbers; `adr/README.md` has the mapping.

- **Steam review-source outage, 2026-09-25 → 2026-11-03**: Valve retired `store.steampowered.com/appreviews` (redirects to the store homepage); every daily run failed and the map froze on run 87 (2026-09-24). Fixed the same day in two steps: PR #28 moved to `GetItems` (run 88 and the scheduled run 89 — filtered counts, nothing below 200 reviews, a provisional ADR-009 rule), then the follow-up PR moved both clients to Valve's documented successor `IUserReviewsService/GetAppReviews`, restoring exact counts and withdrawing the provisional rule (run 90: 3,344 rows, 134 games, minimum 50 in-language reviews; ~18 min per run). Both Steam clients now fail with a named `UnexpectedSteamResponse` error when an endpoint stops answering JSON.

- **Azure hosting outlived its trial**: the site stayed live and `deploy-web.yml` kept deploying well past the end (~2026-09-13) of the 30-day trial the developer activated on 2026-08-14 when the prior free-tier setup stopped being sufficient (confirmed 2026-11-03). The episode is still worth remembering: RFC-002's "VPS migration deliberately deferred" assumed free-tier hosting would last indefinitely, and that turned out not to be guaranteed.

- **Out-of-catalog search shipped** (ADR-011, grill-me 2026-08-08; amends ADR-005 and the Steam Web API notes): the ability to search and get a live heatmap for any Steam game, not just the daily top-100, while keeping searched games warm in the daily rotation. Tracked under parent issue #22 (sub-issue of #1, now closed), split into five vertical slices #23–#27, all closed.
  - **#23** (persist region baselines): `region_baselines (run_id, region_code, baseline_share)` now written alongside `region_scores` every run — previously `region_baseline_share` lived only in memory. Needed so a later on-demand-fetched game can be scored against the same day's baseline without recomputing it.
  - **#25** (relevance-based tracked-game rotation): `games.last_relevant_at`, bumped whenever a game appears in a real top-100 fetch or a user search (#27). The daily job's app_id set becomes `select_app_ids_to_track(top_100, still_relevant)` — a pure, TDD'd union — and `most_played_rank` is explicitly cleared to `NULL` for anything outside today's real top-100. Run history is pruned to the 3 most recent runs after every write.
  - **#24** (weekly Steam catalog cache): `ISteamApps/GetAppList/v2/`, the endpoint this was originally built against, turned out to no longer exist on Steam's live API (confirmed 404). Its replacement, `IStoreService/GetAppList/v1/`, requires a Steam Web API key — the project's first, breaking the Steam Web API notes' "no key needed" premise for exactly one job — and is paginated (50,000 apps/page via `last_appid`/`have_more_results`) rather than single-shot. The developer registered a free key (steamcommunity.com/dev/apikey); `RequestsSteamClient.get_all_apps()` now loops pages, `docs/steam-web-api.md` records the confirmed live mechanics. Live-verified: 179,180 apps fetched and written to `steam_apps`.
  - **#26** (full-catalog search UI): `POST`-free `GET /Home/SearchCatalog?q=` queries `steam_apps` by substring (ILIKE, DB-side), ranked exact-match > prefix > mid-string and capped at 10 by `CatalogSearchViewModelBuilder` (tested; the Postgres repository is untested by design, ADR-006). `map.js` keeps #14's instant local-dataset filter as the first thing shown, then supplements it with a 250ms-debounced call to the new endpoint only once local coverage runs thin, deduped against what's already shown. Headless-verified against the live app.
  - **#27** (on-demand live fetch for untracked games): selecting an untracked result now does something. `OnDemandScoring` is a bit-exact C# port of `analysis/steamheatmap/scoring.py`'s Wilson/concentration math (verified against the same golden test values — `region_baseline_share` is deliberately *not* ported, since on-demand scoring always reads a baseline #23 already persisted). `OnDemandGameFetcher` fires ~29 Steam calls concurrently (`Task.WhenAll`), applies the same 50-review ranking floor as the daily pipeline (ADR-009), and — only if at least one region clears it — upserts (not inserts, to survive a retry or a near-simultaneous duplicate search) into `games`/`region_scores` under the *current* run_id, so the result is visible to every visitor immediately. `map.js`'s clicked result shows its own loading/error state and repaints the map with no page reload. Headless- and DB-verified end to end against the live app: Portal 2 (28/29 regions scored, map fill genuinely repainted, not just the headline text), a real too-few-reviews game showing the honest message and staying clickable to retry, and no regression to an ordinary already-tracked click.

- **Visual pass shipped** (RFC-004, grill-me 2026-07-22, built 2026-07-31; issues #15–#21 closed): a dark, Steam-inspired identity for the homepage — deep navy page, navy surface, Steam blue accent — plus the layout composition RFC-004 was **amended** to allow. The amendment matters: the record originally scoped the pass as restyle-only, and looking at the live page showed the map's lack of weight was structural rather than chromatic, so the decision was revised and #16 re-scoped before any code.
  - **#16** (foundation): `site.css` gains a CSS custom-property token layer, extracted first as a proven no-op (byte-identical render) so the palette change stayed reviewable. Composition: the map is now the page's only framed element and the region panel a plain column beside it; headline, caption and search moved inside the map surface as its header; the row split went to ~3:1; the amber disclosures box dissolved into a muted caption under the headline plus a footer notice — both sentences verbatim and always visible, so #6's requirement still holds.
  - **#21** (map crop, filed mid-pass): Antarctica dropped and the `viewBox` taken from the drawn land's bounds — `0 0 960 500` became `59 0 870 418`. Fiji is excluded from the *crop measurement* only: it straddles the antimeridian, so its bounding box spanned the full width and cost 10.3% of the map's scale. Projection rotation was measured as the non-destructive alternative and rejected — Chukotka and the Aleutians straddle it too, so every central meridian splits something, and the ones sparing Fiji cut Alaska.
  - **#17** (heatmap colors, amends ADR-010's values only): the ramp runs dark→light now, validated rather than eyeballed (single hue, monotone lightness, low end 2.01:1 on the surface; 27 distinct fills spread evenly over real data). `trackedNoSignalFill` and `noDataFill` both went **neutral**, so neither reads as a low rung of the blue ramp — a region with no signal is a different category, not a smaller number.
  - **#18** (typography): self-hosted Manrope, no font request leaves the origin. **One** variable `.woff2`, not the two the RFC assumed — Google's 400 and 700 latin URLs are byte-identical. `OFL.txt` ships beside it. Five-role type scale at 400/700 only.
  - **#19** (loading placeholder) and **#20** (three CSS micro-interactions at 130ms, `prefers-reduced-motion` honored, panel and headline swaps still instant).

- **Map redesign shipped** (ADR-010, grill-me completed 2026-07-18): the map always shows one game's concentration heatmap — landing on the featured game — replacing the region-level choropleth, whose intensity encoded language-community size rather than insight. Single-hue log ramp, fixed clamped domain [×⅛, ×8] (data-backed); fill semantics ramp/white/gray; blended regions signaled by synchronized member-country highlight + region-titled popups (resolves ADR-002's open mechanism); full dataset embedded in the page, no endpoints.
  - **#10** (per-game heatmap spine): pipeline persists most-played rank, view model exposes tracked games + per-game/per-region concentration lookup, map paints one game's ramp with headline and hover popup.
  - **#11** (selected-mode state machine): click enters selected mode (heatmap clears to white/gray, region gets a persistent highlight, side panel shows the region-titled top 10); clicking another region switches directly; hover-preview still works while selected; all three exit routes (re-click, click empty map space, Esc) restore heatmap mode.
  - **#14** (game search typeahead): client-side substring filter over the embedded, rank-ordered game list; empty input shows the rank-ordered top with the featured game first; selecting a suggestion repaints the heatmap/headline, exits selected mode if active, and clears the input; no-match hint discloses the top-100 dataset boundary.

- **MVP** (issues #2–#11, #14 closed): walking skeleton; daily pipeline tracking the real top-100 most-played games across all 30 review languages (keyless API calls, runs green on GitHub Actions, retries transient Steam 5xx/429 with backoff); full 30-region language mapping per ADR-002's concrete table; **ranking eligibility** — a game needs 50+ in-language reviews to rank in a region (ADR-009; the Arabic region drops to the grey no-data treatment as a result, so 29 regions currently display); Wilson confidence finalized at 95%; world map rendered from self-hosted Natural Earth GeoJSON, the D3 code living in `web/wwwroot/js/map.js` behind `initRegionMap(...)`; store links; always-visible disclosures; **production hosting** — live at https://steamheatmap.azurewebsites.net (Azure App Service F1 Linux, France Central, resource group `steamheatmap-rg`), deployed by `.github/workflows/deploy-web.yml` on pushes to `main` touching `web/`. The web app is template-free: no Bootstrap/jQuery, plain CSS only (RFC-003 fully realized).
