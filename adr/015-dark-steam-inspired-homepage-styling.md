# ADR-015: Dark, Steam-inspired visual identity for the homepage

## Context
The MVP shipped functionally complete but visually plain: the default `system-ui` font stack, a white page background, no color legend for the heatmap ramp, instant (untransitioned) state changes on hover/click, and no loading state while the D3 world GeoJSON fetches. The PRD explicitly frames this as a portfolio centerpiece (stories #25–26: "feel smooth and polished, not a bare/default choropleth") — the current look doesn't clear that bar. Grilled on 2026-07-22 to scope what "polish" means, before turning it into an ADR and issues.

## Decision
- **Visual bar**: a solo developer's portfolio project that looks deliberately designed (restrained palette, real typographic hierarchy, smooth micro-interactions) — not a design agency's output, and not default framework styling.
- **Visual language**: Steam's own dark aesthetic (dark navy/charcoal backgrounds, light neutral text, blue accent) as inspiration, without reusing Steam's actual font, logo, or other assets.
- **Scope**: the homepage (`Home/Index` plus the shared `_Layout` chrome it sits inside) only, for now. Color and type decisions land as CSS custom properties (tokens), so a future page inherits them automatically; only the homepage gets dedicated component-level design work this round.
- **No new structural elements**: existing regions (title, disclosures box, search box, map + region panel, footer) are restyled in place. No top navigation bar or logo asset this round — that becomes a natural addition once a second page exists to navigate to/from.
- **Theme**: dark-only, fixed regardless of the visitor's OS preference. No `prefers-color-scheme` branching, no light/dark toggle.
- **Typography**: Manrope, self-hosted (regular 400 + bold 700, latin subset `.woff2` only — no italic, no other weights), used as the single family for every role (headings, body, captions, numerals) — no separate display/body pairing. Chosen after a live side-by-side comparison against Space Grotesk and IBM Plex Sans rendered in the actual dark mockup. Self-hosted specifically to avoid an external font-CDN request, consistent with ADR-010's plain-stack stance. Replaces the generic system-font stack with a deliberate type scale (eyebrow labels, headline, subhead, body, caption) instead of default browser heading sizes.
- **Heatmap fill colors (amends ADR-014's color values for a dark background)**: `trackedNoSignalFill` moves off pure white — on a dark page, white would become the *brightest, most attention-grabbing* fill, inverting its intended "nothing interesting here" meaning — to a muted, receding tone; `noDataFill` and country borders are re-tuned so they read clearly against dark navy instead of the light-page grays. The ramp keeps its single-hue blue family and its continuous rendering via `d3.interpolateRgbBasis`/`d3.scaleSequentialLog` (every concentration value already gets its own interpolated color — not discrete bands — so "more variety" means reshaping the curve's control points, not adding literal steps). Exact hex values and any extra control-point colors are tuned during implementation against real data. ADR-014's *encoding rules* (what each fill state means) are unchanged — only the specific colors are.
- **Accessibility**: WCAG AA is a hard requirement for body text and UI chrome (4.5:1 / 3:1). The heatmap ramp's low end is a legibility judgment call, not a formal contrast target — a country meant to look unremarkable is allowed to recede toward the background, as long as its border stroke still separates it from neighbors.
- **Micro-interactions**: short CSS transitions (~120–150ms, `ease-out`) on exactly three interactions — country hover fill/stroke, the popup's appearance, and the search-results dropdown's appearance. No JS animation library. Region-panel content swaps and headline text swaps stay instant (animating a content replacement reads as sluggish, not polished).
- **Loading state**: a minimal static placeholder (e.g. "Loading map…" on the dark map background, no spinner animation) shown until the GeoJSON resolves. In scope specifically because the PRD's free-tier cold-start risk (story #12) is still unresolved, and a blank rectangle during a cold start reads as broken.
- **Explicitly out of scope this round**: mobile/responsive redesign (existing `flex-wrap` groundwork is left as-is, untouched); a top navigation bar or logo asset; a light theme or theme toggle.

## Alternatives rejected
- **External font CDN (e.g. Google Fonts `<link>`)**: rejected in favor of self-hosting — avoids a third-party runtime request and keeps the stack dependency-free per ADR-010.
- **Uniform formal contrast ratio applied to the heatmap ramp**: rejected — would fight the sequential scale's purpose of letting low-signal regions recede visually.
- **A top nav bar / branded header now**: rejected as more structural scope than a first restyle pass calls for; deferred until a second page exists.
- **A full mobile-responsive pass in the same round**: rejected — touch interaction, popup-positioning math, and tap-vs-hover behavior are a distinct enough problem to warrant their own pass rather than expanding this one's scope.
- **Respecting `prefers-color-scheme` with a light fallback**: rejected — doubles the color-decision surface for a "keep it simple" pass, and Steam itself doesn't offer a real light mode either.

## Consequences
- `map.js`'s fill constants (`trackedNoSignalFill`, `noDataFill`, the ramp array, and the `highlighted`/`selected` stroke colors in `site.css`) all get new values; ADR-014's stated *rationale* for the encoding stands, only the concrete colors change.
- `site.css` gains a token layer (CSS custom properties for color and type) so a future page can inherit the palette/font without redoing that work.
- Two new self-hosted font files (`manrope-400.woff2`, `manrope-700.woff2`) land under `wwwroot/fonts/`, referenced via `@font-face`.
- The next grill session (the search-game feature) inherits this visual language for free since it's homepage-scoped, but any page beyond the homepage only inherits tokens, not component-level polish, until it gets its own pass.
